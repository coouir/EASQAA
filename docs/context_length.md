## 8,192로 다시 돌린 대조 (같은 19건)

입력 토큰이 6,000을 넘은 19건(파일럿 A 재실행 2, B, 영어판)을 `num_ctx` 16,384와 8,192(대조)로 각각 다시 실행했다 (같은 시드·프롬프트, 서버 재시작 없음).

| | 원래(8,192) | 다시: 16,384 | 다시: 8,192 (대조) |
|---|---|---|---|
| 정답 | 9/19 | 9/19 | 7/19 |
| 실행 실패 | 10 | 9 | 11 (모두 예산 초과) |
| 원래와 정오가 다른 실행 | - | 0 | 2 |
| 원래와 최종 답이 같은 실행 | - | 18/19 | 17/19 |
| 원래와 도구 호출 순서가 같은 실행 | - | 8/19 | 13/19 |
| 실행 하나의 입력 토큰 최댓값 | 7,182 | 7,152 | **8,126** |

- **8,192 대조 실행에서 입력이 8,126 토큰까지 갔다.** 출력 100~400 토큰만 더해도 8,192를 넘는 길이다. 긴 실행(도구 15~20회)은 궤적에 따라 8,192에 닿으므로 test에서도 위험하다.
- 16,384에서 정오가 뒤바뀐 실행은 0건이고 정답 수는 같다(9/19). 도구 호출 순서가 원래와 같은 비율은 8/19로 낮지만(같은 8,192 대조는 13/19), 최종 답은 18/19가 같고 차이는 모두 긴 실행의 경로 분기다. `num_ctx`를 바꾸면 수치가 미세하게 달라져 궤적이 갈리는 것은 서버 재시작 때와 같은 종류의 현상이며 이 표본에서 정확도에는 영향이 없었다.
- 16,384 결과와 8,192 대조의 최종 답은 16/19가 같다(서로 다른 실행 사이의 변동과 같은 크기).

## GPU 메모리와 결정

- 16,384에서 모델을 올린 뒤 `nvidia-smi` **7,301~7,365 MiB / 10,240 MiB**, `ollama ps` 모델 크기 7.39 GB. 여유 약 2.9 GB.
- **결정 (사용자 규칙: 7,000 초과 실행이 있으면 16,384)**: `configs/default.yaml`의 `llm.num_ctx`를 8,192 → 16,384로 올린다. SPEC §7.1·§15의 기본값(8,192 유지)과 다르므로 `docs/deviations.md`에 기록한다. 동결 뒤에는 바꾸지 않는다.
- 남은 위험: 16,384도 넘는 실행은 dev 자료에서 보이지 않는다(최대 7,182). 본 실행 기록의 `prompt_tokens_max`(#84)로 확인한다.
