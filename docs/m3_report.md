**분류기 관찰** (규칙은 dev로만 조정, 아직 조정하지 않음)
- 조건 1 첫 이탈: 해석 13, 계산 5, 도구 선택 3, 실행 실패 2. 조건 2: 해석 13, 계산 3, 도구 선택 4. **해석 단계가 많은 것은 해석이 항상 가장 이른 턴이라서**, 어휘를 정확히 맞추지 못하면(특히 L3 반복·L4/L5 분기 문항에서 target/region 선택) 뒤의 다른 이탈보다 먼저 잡히기 때문. 해석 문구·어휘가 지나치게 엄격한지 사용자가 검토하는 것이 좋겠다.
- 입력 오류 하위 범주 (조건 2): 누락 11, 오탐 3, 위치·크기 2, 복합 3, unknown 3. unknown 3건 중 2건은 라벨과 상자 오류 개수가 0인데(IoU ≥ 0.75의 미세한 크기 차이) 정수 정답(가장 긴 선박 길이)이 바뀐 경우다. SPEC의 세 종류로는 설명되지 않는 "미세 크기 차이"이며, 정수 정답의 정확 일치 규칙 때문에 생긴다.
- 일괄 계획(조건 4·5)은 이번 파일럿에 없으므로 통계가 없다.

**튜닝 권고 (사용자 판단)**
1. 예산 초과가 실패의 대부분이다. 프롬프트에 "필요한 값을 얻으면 바로 답하라"를 강조하거나, 호출 상한의 최소 여유를 늘리는 것을 dev에서 시험할 수 있다(SPEC 값은 `max(2g, g+3)`이라 바꾸면 deviations에 기록).
2. L5는 0/5이므로 사례 분석 전제로 두거나 쉬운 템플릿으로 교체할지 결정.
3. 정수 길이 문항(`l2_longest_length`)은 5% 허용이 없어 IoU ≥ 0.75의 미세 차이에도 오답이 된다. float 형으로 바꾸거나 허용 오차를 두는 것을 검토.
