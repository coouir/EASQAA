# 예산 초과 분석과 프롬프트 조정 (이슈 #68)

## 1. 파일럿 A의 예산 초과 22건 (조건 1: 7, 조건 2: 15)

전체 사례와 호출 순서는 `docs/budget_cases_pilot_a.md`.

| 원인 | 조건 1 | 조건 2 | 합 | 뜻과 대표 양상 |
|---|---|---|---|---|
| 불필요한 탐색 (`exploration`) | 5 | 4 | 9 | 필요 없는 호출을 이어 함. L5에서 `image_stats`로 사분면 잡음을 다 구한 뒤 `calc argmax`를 쓰지 않고 사분면마다 `detect_ships`·`sizes`를 호출, `noisiest_region`을 도구 영역 이름으로 착각(오류) |
| 같은 호출 반복 (`repeated_call`) | 2 | 7 | 9 | 같은 도구·같은 인자를 되풀이. 없는 `spatial_query argmax`, `calc count`에 `cmp`·`threshold`를 붙여 같은 오류를 4~6번 재전송, 선박 하나씩 `nearest_to`를 두 번씩 |
| 종료 실패 (`termination_failure`) | 0 | 4 | 4 | 필요한 호출은 다 했는데 답하지 않고 계속 호출 (`calc count`를 오류 나는 형태로 반복) |
| 오류 반복 (`error_loop`) | 0 | 0 | 0 | 오류가 3번 이상이면서 위 셋에 안 걸린 것 없음 |

- 문항 유형: L5 8건, L2 5건, L3 5건, L4 4건. 예산 초과 실행의 평균 호출은 10.5회로 상한(평균 10.5)에 딱 걸렸고 평균 `gold_calls`는 5.2였다. 즉 **상한이 빠듯해서가 아니라 반복·탐색으로 gold의 두 배에 이르는 폭주**였다.
- 조건 2(탐지 상자)가 더 많은 것은 상자가 라벨과 달라 결과가 기대와 어긋날 때 같은 호출을 되풀이하는 경향이 있기 때문으로 보인다(같은 문항이 조건 1에서는 정상 종료).

## 2. 프롬프트 조정 (dev에서만)

`agents/prompts/common.md`에 추가: 작업 방식 규칙(필요한 값을 얻으면 바로 답한다, 같은 호출을 되풀이하지 않는다·오류는 고쳐서 다시, 나열된 연산만 쓴다·`spatial_query`의 질의 이름을 명시, 필드가 있는 도구를 고른다, 사분면은 하나씩 호출해 `calc`로), `calc` 예시(filter로 개수 세기, argmax + labels, `noisiest_region`은 도구 영역이 아님). `stepwise.py`: 도구 오류 뒤에 한 줄 안내(단계별에만; 일괄 계획은 실행 중 오류를 볼 수 없다).

| 원래 프롬프트 | 6/16 / 7 | 1/16 / 15 | 22 |

## 4. 예산 공식 max(2g, g+5)일 때 (보고만, 적용 안 함)

공식 `max(2g, g+3)`은 그대로 두고, 같은 프롬프트로 문항의 예산만 `max(2g, g+5)`로 바꾼 파일(`data/questions/dev_g5.json`, 90문항 중 58문항의 예산이 달라짐; g=1: 4→6, g=2: 5→7, g=3: 6→8, g=4: 8→9)로 조건 1·2를 다시 돌렸다. 시드가 같아 예산 초과 전까지 궤적은 같다.

| | g+3 (재실행) | g+5 |
|---|---|---|
| 조건 1 정확도 / 예산 초과 | 78/90 / 5 | 79/90 / 4 |
| 조건 2 정확도 / 예산 초과 | 57/90 / 9 | 57/90 / 8 |
| 평균 도구 호출 | 4.31 / 4.44 | 4.32 / 4.48 |
| 평균 시간(s) | 13.1 / 14.3 | 13.0 / 14.3 |

**정답이 바뀐 실행은 단 1건**(조건 1 D-L4-002, 예산 초과 → 정답). 예산 초과 실행은 상한을 2~3회 늘려도 끝나지 않는 폭주이므로 상한을 늘려도 얻는 것이 거의 없다. **권고: 공식을 그대로 둔다.**
